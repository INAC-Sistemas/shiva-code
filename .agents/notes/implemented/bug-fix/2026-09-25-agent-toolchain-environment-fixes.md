# Agent Note: the agent's shells share one toolchain, one build mode, and writable package caches

Status: implemented

## Problem

A desktop `npm run dev` session asked to build a shopping-list system reached the plan in about nine minutes and then spent about thirteen more minutes on the environment without delivering a screen. The session log showed four causes:
- **NODE_ENV leaked into agent commands.** `electron-vite dev` sets `NODE_ENV=development` (and `NODE_ENV_ELECTRON_VITE`), and the Harness passed it to every agent process. A project's `next build` then ran with a non-standard `NODE_ENV` and failed prerendering `/_global-error` with `Cannot read properties of null (reading 'useContext')`.
- **The terminal tab ran another pnpm.** The agent's `bash` tool inherits the Harness `PATH`, where `dsh-desktop-market-installer` puts `<DSH_HOME>/.desktop-bin` first (pnpm 10). Agent terminal tabs start login shells, and the user's profile reordered `PATH` so corepack's pnpm 11 won. pnpm 11 prompted to reinstall the `node_modules` pnpm 10 had created and then blocked ten packages under its `minimumReleaseAge` policy. The agent waited 60 s and 180 s on `terminal_wait_for` while the tab sat at a prompt.
- **An aborted tool printed `Error: [object Object]`.** `signal.throwIfAborted()` throws the abort reason, here `{ kind: 'user' }`, and the core tool error formatter stringified non-Error objects without a `message`.
- **Package-manager caches were read-only.** `workspace-write` grants only the workspace and the temporary areas, so npm failed with `EROFS` on `~/.npm/_cacache`, and the agent worked around it by pointing caches into the project.

## Decision

**The desktop strips its build mode from the Harness environment.** `buildHarnessSpawnOptions` removes `NODE_ENV` and `NODE_ENV_ELECTRON_VITE` next to `ELECTRON_RUN_AS_NODE`.

**Agent terminals re-export the Harness `PATH` after the login profile.** `AgentPtyRegistry.create` writes `export PATH='<Harness PATH>'` before the command for known POSIX shells (sh, bash, zsh, dash, ksh, mksh, fish). Windows shells and unknown shells are left alone. User-opened terminal tabs are unchanged. The desktop ships a pinned `dsh-better-sidebar` 0.15.5 that cannot be repacked from this checkout, so the change lands in the plugin source, its tracked `lib/index.js`, and the desktop's `dsh-better-sidebar+0.15.5.patch`. Until the pin lifts, `/00-start-here` and `/04-construcao` also tell the agent to start the app with the absolute pnpm path `command -v pnpm` prints in `bash`, and to `terminal_read` after a `terminal_wait_for` timeout.

**The tool error formatter renders plain objects as JSON.** `errorMessage` in `dsh-tools` returns `JSON.stringify(error)` for objects without a string `message`, so a cancelled call reads `Error: {"kind":"user"}`.

**`workspace-write` can grant deployment-configured extra roots.** `dsh-sandbox-policy` gains `extraWritableRoots` (absolute paths, created at load, a relative entry fails the load). `resolve()` puts them on `SandboxExecutionPolicy.extraWritableRoots` under `workspace-write` only. `writableRoots` (Seatbelt and the fs fence), the bwrap profile, and the Landlock grants include them, and the model-visible policy line names them. The desktop sets them to `~/.npm`, `~/.local/share/pnpm`, and `~/.cache/pnpm` on Linux and the macOS equivalents. The product owner chose this over caches inside the workspace or in `/tmp`, which keep the sandbox narrower but download every package again per project or per command.

The bundled Harness 0.1.2-alpha.4 is not built from this checkout, so each package change is mirrored into `desktop/node_modules` and recorded as a desktop patch: `@deepseek-ai+dsh-tools`, `@deepseek-ai+dsh-sandbox`, `@deepseek-ai+dsh-sandbox-local`, and `@deepseek-ai+dsh-sandbox-policy`. `patch-package` cannot fetch these versions from a registry, so the patches were generated by diffing the original tarballs in `desktop/packages/harness-0.1.2-alpha.4/` against the patched `node_modules`.

## Alternatives considered

**Configure `shellArgs` to skip the login profile.** Rejected: the same setting drives the user's own terminal tabs, which would lose their aliases and prompt.

**Grant the whole home directory, or leave the caches to each agent.** Rejected: the first widens the sandbox beyond the need, and the second is what produced caches inside the project.

## Consequences

- The Windows ACL backend ignores `extraWritableRoots`; the package READMEs record it as a known limitation.
- A user who moved the npm or pnpm cache through `XDG_*` or npm config still hits EROFS until the desktop list names that path.
- The `export PATH=…` line is visible at the top of every agent terminal transcript.
